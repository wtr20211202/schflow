# ADR-0020：批次长尾治理七项

- 状态：accepted（先行流水线决策 #20，2026-10-21，14 小时批次复盘）
- 落点：D
- 关联：0007、0014、design.md §8

## 背景

复盘一条 11 支批次：关键路径不是夜间故障，而是**合并受阻等人工裁决 5 小时**与合入后回归尾巴 3 小时——根因：两条提案各自实现同名新模块（一方提案文本已写「统一走对方」但对方未落地）；合并冲突按协议等人，台账之外无强提醒；共享模块改动漏了导入方用例的复验。

## 决策（七项）

① 派发期软依赖 + foundation 标记：正文引用未落地能力 → 暂缓或任务书指定唯一实现，禁止另建同职责模块；② 合并期窄口径自动裁决：同一新增模块双实现且一方为更高优先级/方案超集 → 超集为主干收编、另一方 rebase 删重复；仅用户可见行为实质分歧才 [受阻]；③ 受阻即通知（多通道，同因防重）；④ 调用点补测：共享模块改动查导入方，把导入方用例并入合并复跑；⑤ 修复器部分提交通道：残余仅剩已知环境例/基线红时，提交已验证修复并标注残余，不整轮丢弃；⑥ 回归分片按实测域时长均衡重排 + 机读基线自动对账复跑；⑦ 重量级门禁排队/超时 → 标记待补不阻塞，合并后在主仓库补跑（失败走修复路径，不回滚合并）。

## schflow 映射

①→judge 钩子①输入；②→judge 钩子②；③→sink；④→合并闸复验命令组装；⑤⑥⑦→回归治理/Profile。
