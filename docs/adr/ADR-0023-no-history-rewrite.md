# ADR-0023：禁改写已推历史 + 非快进树等价消解

- 状态：accepted（先行流水线决策 #23，2026-10-25）
- 落点：E
- 关联：0010

## 背景

修复器完成提交被推送后，又把自己已推的提交 amend 成内容等价新提交（同父+树哈希逐位一致）——例行推送被非快进拒绝；旧规则「非快进一律等人」会把可确定性消解的场景挂起整夜。

## 决策

① 修复器提交纪律：只许在 HEAD 之上新增提交，禁止 amend/rebase/reset 改写任何既有提交（历史可能已上远端）；重派发现修复已提交且树干净 → 直接返回既有哈希勿重提；② 中断重派的任务书必须注明「已完成的提交不要再做一遍」；③ 非快进树等价消解通道：本地多出的提交若与远端同父且树哈希一致且主树干净 → 对齐远端（零损失），否则才升级人工。

## schflow 映射

执行器提交纪律（引擎侧 commit 前查 `git log --grep "({id})"` 幂等）；推送前等价性检查入合并队列。
