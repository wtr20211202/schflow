# ADR-0013：配额与夜间窗口的设立与撤销史

- 状态：superseded-by-0030（先行流水线决策 #13）
- 落点：D
- 关联：0005、0030

## 背景与演化

为控全量回归负载曾设：数量封顶（次日否决）、24h 兜底 + 夜间窗口（夜间不启动全量）→ 后发现「全量在跑期间不领新任务」的老问题已被滚动批次补位解决，窗口存在的理由消失 → **整体撤销**（全量 24h 随停顿点启动，代价用户权衡后接受）→ 数项参数随 0030 按需制再调（兜底放宽至 72h、修复轮数 2→3、瞬断重派上限 2→10——客户端连续故障日用 2 次太快耗尽）。

## 教训

**为缓解症状设的窗口类机制，在根因被别的修复消解后要主动拆掉**；参数放宽类调整要记动因（重派上限 10 = 扛过整段客户端故障窗口）。

## schflow 映射

无窗口概念；重派上限/修复轮次为 Profile 参数，默认值继承本条实测。
