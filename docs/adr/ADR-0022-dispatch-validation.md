# ADR-0022：派发参数严格校验（path 源教训）

- 状态：accepted（先行流水线决策 #22，2026-10-25）
- 落点：E

## 背景

派发通道从「内嵌脚本」改为「引用脚本文件 + 参数平铺」后，tick 连续六次参数形态写错被静默拒绝（连废六轮派发）；且旧通道对未知参数**静默忽略**（拼写错的开关静默落默认值）——两种失败形态都长期潜伏。

## 决策

派发契约**严格校验**：未知键报错（不静默忽略）；必填键缺失报错；调用模板/自查清单随契约同步。并行门禁开关拼写错当场被抓 vs 静默跑错档位——宁可派发失败可见，不要执行偏离无声。

## schflow 映射

schflow 的派发是引擎内函数调用（编译期类型约束），此教训泛化为两条：①配置 schema 严格校验（zod，未知键拒绝）；②外部契约（L3 delegate 的 poll 五态）校验失败=显式报错挂起。
